# pragmatic-review

按仓库规则、已确认契约和通用质量基线审查代码，支持独立评审及开发规范统计。技能维护检查方法、证据门槛与工程改进模式，项目规则由目标仓库维护。

## 使用

提供范围、关注方向和所需输出粒度。范围默认当前工作区；明确指定暂存区或变更集合时，按该范围核对。

### 代码评审

```text
使用 $pragmatic-review。
审查当前未提交改动，结合仓库开发规范和已确认契约，
给出值得优先处理的问题、证据和改进建议。
本次交付评审结论。
```

问题类别说明性质，严重度按实际影响判断。关注特定方向时，可以指定“暂存区的后端可靠性”或“指定变更的 deep review”。

### 规范概览

```text
使用 $pragmatic-review。
归纳当前未提交代码中的开发规范问题，
以“问题类别、表现、举例”返回概览。
```

该请求进入规范统计模式，按实际发现区分明确违例、维护性风险和功能缺陷。正在施工的内容注明观察范围，数量按实际计数状态表达。

### 数量统计

```text
使用 $pragmatic-review。
范围：<指定 diff 或代码集合>
统计单位：<问题位置、受影响文件或独立问题>

请逐项核对开发规范问题，按类别汇总数量，
给出规则依据与代表性举例，并注明统计快照。
```

### 方案、诊断与验证评估

```text
使用 $pragmatic-review。
材料：<相关代码、设计或复现证据>
目标：<需要评估的工程问题>

请结合仓库架构、当前成本和验证证据评估可选方案或验证方法。
本次交付分析与建议。
```

## 维护

通用质量与评审经验更新对应基线、模块或模式，项目规则更新目标仓库。保留模式的适用范围、来源、状态和验证边界；分支或常量的质量判断由适用规则、业务语义和实际成本支持。
