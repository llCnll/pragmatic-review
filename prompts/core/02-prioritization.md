# Finding Severity

Assess severity independently from the problem category. Use the applicable contract, observed path, affected users, failure cost, likelihood, and available safeguards.

| Severity | Meaning |
| --- | --- |
| P0 | Evidence-supported critical failure requiring immediate containment, such as widespread data loss or a severe active exposure |
| P1 | Material behavior, security, data, availability, or maintenance risk to resolve before delivery |
| P2 | Local behavior or maintenance problem with a clear practical correction |
| P3 | Low-impact improvement or routine compliance cleanup relevant to the requested scope |

A category identifies the issue's nature: behavior, complexity, duplication, ownership, observability, performance, or project compliance. Any category can carry the severity supported by its actual impact.

Rank findings by operational and user impact, maintenance cost, evidence strength, and correction cost. Apply the requested output mode after ranking. Standards audits cover applicable rules and requested categories at the chosen granularity.
