# 接口设计模式

按已确认契约和仓库规则评估接口业务语义及字段投影。文档结构、载体和表达遵循项目文档规则。

## 互斥业务模式

适用于同一接口按 mode、type 或 action 处理多种业务模式。

共享同一用例和生命周期的模式可共用接口，独立能力按职责拆分。各模式明确进入条件、生效字段、必填条件、接受后忽略或拒绝的字段，以及响应差异。

最小验证覆盖各模式成功、缺少模式字段、额外字段处理和错误响应；忽略字段按契约保持零副作用。

## 缺失、空值与清空

适用于更新、补丁、筛选和批量操作。

按业务语义分别定义字段缺失、null、空对象、空数组和空字符串的行为。生效字段按对应类型与规则校验，接受后忽略的字段保持忽略语义。

例如：字段缺失保持原值，[] 清空列表，null 按该字段的约定处理。

最小验证逐项覆盖上述形式与正常值，核对实际结果。

## 稳定资源引用

适用于下游需要引用候选或上游对象的接口。

沿来源传递稳定标识；采用 resource_type 和复合 resource_id 的契约时，整体传递这些值。展示名称承接展示用途，标识转换采用已确认映射。临时标识核对生命周期与当前用途。

区分外显 ID、内部主键、第三方 ID、业务编号、临时 ID、会话 ID 和幂等 ID，说明来源、可写性和下游用途。

最小验证覆盖正确引用、错误类型、资源缺失、范围校验和允许的转换。

## 服务端事实与计算字段

适用于指纹、状态汇总、编号、外部事实和执行快照。

调用方提交页面输入与稳定引用，服务端生成或校验其拥有的事实。完整配置、局部输入、页面状态和执行快照按用途分别建模。可写性由事实所有者及已确认契约决定。

最小验证覆盖合法输入、伪造事实的处理、生成结果与来源一致性，以及执行快照追溯。

## 时间与数组传输

适用于表单、OpenAPI 示例及跨语言调用。

时间格式、时区和无值形式按项目契约统一；数组按真实载体和项目约定编码。采用 repeated key 时，对象数组每项一个 JSON object，标量数组每项一个标量。single key + JSON array 等形式按当前兼容范围处理。

编码调整在兼容评估完成后实施。最小验证覆盖有值与空时间、对象与标量数组、空数组以及既有客户端。

## 异步受理与完成

适用于异步任务、批量处理、导入导出和需轮询的外部调用。

受理成功明确任务身份与查询入口，最终结果通过详情或结果查询取得。重试沿执行身份与成功检查点恢复，并保留历史记录。同步完成的接口直接返回最终结果。

最小验证覆盖受理、成功、失败、超时、重复提交、重试和部分失败，核对调用方识别的实际状态。

## 页面 VO 与业务命令

适用于共用创建／更新表单，或页面字段集合大于某次操作输入的场景。字段一致的简单接口可沿现有输入结构处理。

- 页面 VO 明确操作识别方式，例如 id=null 创建、id 有值更新。
- View 根据操作及显式字段投影为 CreateCommand 或 UpdatePatch；更新包含本次可更新的显式字段。
- 已声明且当前操作接受后忽略的字段在入口完成投影；Service、指纹、快照、持久化和外部请求承接有效字段集合。
- Service Command 按业务需要保持严格，页面兼容与操作识别由入口承接。
- 额外字段按具体操作契约处理；权限、资源、状态和可更新值校验失败时返回对应错误。

最小验证覆盖操作分派、接受后忽略、更新省略字段保持原值和额外字段处理；核对最终 Service 输入、任务快照和外部 HTTP payload 中的有效字段集合。

| --- | --- | --- |
| 互斥模式、空值、引用、服务端事实、传输与异步 | CN 接口契约与联调经验 | 已验证 |
| 页面 VO 与业务命令 | 页面表单与业务命令字段投影 | 试用中；已在一个创建/更新场景完成边界验证，需跨场景复用后再升级。 |

具体字段、路径、类型和业务规则仍以当前项目正式契约为准。
