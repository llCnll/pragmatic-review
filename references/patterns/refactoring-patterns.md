# 受控重构

适用于多用例、异步、外部调用、持久化、重试或高影响副作用交织，且已有职责、状态或验证成本问题的模块。局部 CRUD 和纯计算调整采用相称的局部流程。

## 基线与边界

1. 核对契约、状态、权限、数据、外部副作用、测试和发布基线。
2. 明确需保持的接口、响应、错误、快照与外部结果。
3. 按用例、变化点和副作用划分职责与事实所有者。
4. 收敛契约与状态，再调整业务、数据访问及适配边界。
5. 异步流程明确成功检查点、重试、审计、幂等和恢复。
6. 切换前验证兼容、失败边界、恢复、观测及回滚。
7. 完成稳定入口切换，移除已废弃实现，运行路由沿最终设计收敛。

工厂、容器、基类或消息系统由真实复用、依赖或协调需求支持。行为变化按契约变更确认；目录和类的调整承接已明确职责。

## 最小验证

业务代码、契约、测试和历史数据兼容共同核对。验证到业务结果、外部调用次数、审计与持久化状态，并在对应环境核对实际切换和人工恢复。

成功标准：稳定入口沿最终实现运行，原契约、状态和副作用边界保持，实际恢复路径具备对应证据。

## 来源与状态

来源：复杂业务模块重构复盘。状态：试用中；当前项目已验证，尚需跨项目复用验证。
