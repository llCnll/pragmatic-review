# 跨框架借鉴 UI 设计模式

## 适用场景

在游戏引擎、Canvas 或其他宿主平台界面中借鉴 Apple 的设计体系，目标是改善一致性、交互和维护成本，同时保留宿主平台与既有架构。

## 推荐做法

先区分参考来源：HIG 定义界面与交互指导；SwiftUI 提供声明式视图、状态观察和组件组合等框架能力。跨框架迁移的是设计原则，自动布局、系统无障碍支持和状态更新机制须在目标运行时单独确认。正式行为与验收仍由项目规格定义，方案归位到项目设计。

| 决策 | 目标运行时中的做法 |
| --- | --- |
| 布局与尺寸 | 按可用空间、安全区及原生控件保留区域布局；棋盘或场景内部可使用固定逻辑坐标。触控尺寸按最终屏幕映射评估，Apple 的 pt 与引擎单位、物理像素按真实缩放关系转换 |
| 样式与组件 | 按正文、辅助、强调、危险等语义定义样式；共享按钮、卡片、弹窗的行为与状态，允许游戏保留自己的视觉表达。优先使用现有布局能力、预制组件和必要的小型组合 |
| 状态所有权 | 业务或对局状态由其模型、服务或引擎持有；视图持有展示所需的局部状态。渲染读取状态，操作通过明确入口改变状态；普通界面刷新保持当前业务或对局状态 |
| 反馈与可感知性 | 自定义按钮具有按下、禁用及必要的处理中状态；关键结果同时使用文字、图形等表达。错误提示提供可执行的恢复操作 |
| 更新范围 | 声明式描述与增量更新分开评估。存在帧耗时、节点创建或状态丢失问题时，再依据测量和生命周期边界决定是否调整渲染方式 |

## 适用边界

- 宿主平台的安全区、导航、原生入口和性能约束优先于参考外观；iOS 控件行为、玻璃效果、系统字体或品牌资源需分别判断适用性和使用条件。
- Canvas 或游戏引擎自绘 UI 的读屏语义、字体适配和无障碍能力在目标运行时逐项验证，支持声明对应实际证据。
- 重复绘制代码用于评估公共组件；技术栈、声明式框架和跨游戏样式的调整由当前目标与实际成本支持。
- 静态或低频页面可继续整体绘制；涉及动画、异步回调、输入监听或原生控件时，须明确视图身份、创建、隐藏和销毁边界。

## 最小验证

按本次改动选择相关场景；关键状态或生命周期的大范围调整须写明以下对应验证及失败恢复边界。

| 变更 | 最小操作与可观察结果 |
| --- | --- |
| 布局与主题 | 在目标设备覆盖不同屏幕比例、安全区和支持的主题；文字可读、内容完整可见，原生区域可用，重要状态结合文字或图形表达 |
| 触控与反馈 | 在最终缩放后的界面点击控件中心及边缘，连续点击并检查禁用和处理中状态；命中符合显示区域，单次操作对应一次有效提交 |
| 状态与生命周期 | 在业务进行中刷新、切页、前后台切换，并让延迟回调在离开页面后完成；依据退出与恢复规格核对状态，业务状态沿规格保持，监听与原生控件按生命周期维护，回调核对当前视图身份 |
| 渲染性能 | 改变节点重建、动画或更新方式时，在同一目标设备和场景对比改动前后的帧耗时、节点数量及重复进出后的资源占用；收益与代价由测量记录支持 |

关键状态或生命周期验证失败时停止扩大改动，恢复已验证的实现；回退保留真实存档与业务状态。运行时验证记录留在项目，各目标环境的验证结论对应其执行证据。

## 来源与状态

状态：试用中。已核对 Apple 官方指导，并在一个 Cocos Creator / TypeScript 项目中实施公共主题、控件与安全区映射；该项目的 Web 运行时验证覆盖 9 个游戏、两种主题、输入与重绘状态、原生 API 测试替身及视觉检查。当前证据支持该项目中的复用与状态边界；跨项目适用性、微信原生能力、真机输入与性能收益仍未验证。
