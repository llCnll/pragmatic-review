# 分层与模块边界

适用于需要确定接口、业务用例、数据访问或跨模块调用职责的场景。

## 职责

- 协议层负责输入输出适配、鉴权入口及协议错误转换。
- 业务层负责业务规则、用例编排和状态变化。
- 数据访问层负责查询与持久化细节。
- 稳定契约承接层间依赖，底层细节归事实所有者。

以仓库架构为基线，简单逻辑可直接表达，分层用于真实职责隔离。Handler 调用业务用例，业务用例推进状态与事务，Repository 承接查询和 SQL 细节。

## 多供应商协议与共享设施

适用于多供应商调用需要复用传输、限流、观测或脱敏能力的场景。

各供应商适配器维护端点、方法、请求转换、能力映射、客户端与响应适配。共享设施承接供应商无关能力，组合根注入通用契约并装配实际适配器。

业务编排调用能力契约。供应商账户、鉴权和协议事实归对应适配器；同一能力沿唯一声明复用。单一简单集成可直接适配，共享设施用于已存在的共同需求。

能力检查在网络请求前执行，缺项返回明确配置错误。

## 最小验证

核对调用方向、事实所有者、稳定契约、可替换性和实际依赖图。多供应商场景核对共享层的通用契约、协议唯一声明、组合根装配及能力缺项的执行前失败。

共享设施边界为试用中模式，已在同一项目两个供应商中验证。

## 来源与状态

来源：多供应商集成的协议边界拆分实践。状态：试用中；已在同一项目的两个供应商集成中验证，仍需在不同项目或技术栈复用后评估升级。
