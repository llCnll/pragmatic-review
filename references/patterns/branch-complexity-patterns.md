# 复杂业务分支的语义拆分

适用于按类型、状态、错误类别或配置模式排列的复杂分支，且存在可重复变化点的场景。

## 结构选择

先识别决策语义，再选择最小结构：

| 分支语义 | 可选结构 |
| --- | --- |
| 资源或操作类型分派 | Strategy 或只读处理器表 |
| 状态聚合和优先级 | Facts、有序规则表和 Aggregator |
| 多条件业务结果 | 独立 Policy |
| 固定枚举、名称或文案 | 只读 Mapping |
| 取消、租约、权限和写入前保护 | 显式校验与早返回 |

少量稳定分支可直接表达，策略用于真实独立变化点。上传、投影、状态机和错误处理各守职责；执行编排拥有外部写入、状态、审计和恢复，纯投影负责输入输出转换。

## 适用边界

结构调整保持已确认的输入输出、未知值、异常传播、调用次数和状态优先级。拆分同时明确依赖、事实和副作用所有者，映射变化同步核对历史数据、接口响应和测试夹具。

## 最小验证

每种类型、状态或模式覆盖正常输入，补充未知类型与非法输入。核对规则优先级、Mapping 默认值与错误语义，执行相关测试和静态检查。

涉及外部副作用时，验证保护分支的零写入、成功检查点结果复用，以及调用次数、审计和链路关联。涉及历史数据时，验证快照与空值兼容，保留真实来源、时间和内容。

## 来源与状态

来源：复杂业务模块重构中的类型分派、状态聚合、业务策略和固定映射拆分经验。

状态：试用中；当前项目已通过相关回归测试、静态检查和编译检查，尚需在其他复杂业务模块中复用验证。
